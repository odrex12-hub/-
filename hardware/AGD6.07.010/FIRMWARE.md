# АГД6.07.010 — прошивка: что поддержано в PX4, что нужно дописать

Проверено по исходникам PX4-Autopilot (ветка `main`, коммит `27d3a62`, 2026-09):
`src/drivers/*`, `boards/px4/fmu-v6x/init/rc.board_sensors`, `boards/px4/fmu-v6x/src/i2c.cpp`.
Программа управления и связки блоков (ИИ ↔ Pixhawk ↔ плата) — отдельный этап, этот файл — исходные данные для неё.

## 1. Устройства на шине I²C платы (разъём J306 -> порт I2C Pixhawk 6X)

| Адрес | Микросхема | Что измеряет | Драйвер PX4 | Что делать |
|---|---|---|---|---|
| 0x40 | U102 INA228 | вход 14S: ток (шунт RS101 10 мОм), напряжение VIN_PROT | `ina228` есть | запуск вручную, `-a 0x40` |
| 0x41 | U204 INA228 | канал ИИ 12 V: ток (RS201 15 мОм) | `ina228` есть | запуск вручную, `-a 0x41` |
| 0x45 | U205 INA228 | шина А +12V: ток (RS202 10 мОм) | `ina228` есть (адрес по умолчанию 0x45) | запуск вручную, `-a 0x45` |
| 0x49 | U804 ADS1115 | AIN0–2: токи ключей IS1–IS3 (клапаны, огни), AIN3: V12_MON (шина Б, делитель 100k/22k) | `ads1115` есть | **`ADC_ADS1115_EN = 0`**, запуск вручную `-a 0x49` |
| 0x48 | U702 TMP117 | температура платы | **нет** (есть только `tmp102`, `mcp9808`) | написать драйвер (≈150 строк, по образцу `tmp102`) |
| 0x44 | U703 SHT4x | температура/влажность отсека (конденсат) | **нет** (есть только `sht3x`, другой набор команд) | написать драйвер (по образцу `sht3x`) |
| — | J701, J702 | выносные датчики (радиатор ИИ, воздух) | зависит от датчика | выбрать датчик с драйвером PX4 или свой |

**Конфликт адресов (важно):** на Pixhawk 6X при `ADC_ADS1115_EN = 1` скрипт `rc.board_sensors`
выполняет `ads1115 start -X` с адресом по умолчанию **0x48** — на этом адресе стоит TMP117.
Поэтому автозапуск выключается, ADS1115 запускается вручную с адресом 0x49.

Автозапуск `SENS_EN_INA228 = 1` запускает `ina228 -X -b 1/-b 2` по адресу 0x45 для штатных цифровых
power module (POWER1/POWER2). Наши INA228 — на отдельной шине; запускаются своими строками (п. 2),
номер батареи (`-t`) не должен совпадать с power module.

## 2. Запуск (файл `/fs/microsd/etc/extras.txt` на Pixhawk)

Номер внешней шины I²C, на которую выведен порт I2C Pixhawk 6X, уточнить на стенде:
`i2cdetect -b 1`, `-b 2`, `-b 3` — ищется набор адресов 0x40, 0x41, 0x44, 0x45, 0x48, 0x49
(в PX4 для fmu-v6x внешние шины: 1, 2 (общая), 3; шина 4 — внутренняя).

```
# N — номер шины, найденный i2cdetect
ina228 -X -b N -a 0x40 -t 3 start    # вход 14S
ina228 -X -b N -a 0x45 -t 4 start    # шина А +12V
ina228 -X -b N -a 0x41 -t 5 start    # канал ИИ
ads1115 -X -b N -a 0x49 start        # токи ключей, напряжение шины Б
```

Калибровка INA228 (параметры драйвера `INA228_*`): шунты 10 мОм (U102, U205) и 15 мОм (U204),
максимальный ток 5.5 A / 5.5 A / 3.7 A.

## 3. Выходы Pixhawk -> исполнительные устройства платы

| Функция | Выход Pixhawk | Узел платы | Настройка PX4 |
|---|---|---|---|
| Клапан 1, 2 | AUX (`VALVE1_CTL`, `VALVE2_CTL`) | ключи U801, U802 (BTS5030-1EJA, шина Б) | функция выхода — реле/сервопривод (вкл/выкл) |
| Огни | AUX (`LIGHTS_CTL`) | ключ U803 | реле |
| Насос | AUX (`PUMP_PWM`) | только сигнал ШИМ на ESC насоса (J806) | ШИМ |
| Вентилятор | AUX5 (`FAN_CTL`) | Q801; аппаратно включается и при перегреве (TMP117 ALERT) | реле |
| Нагреватель | AUX6 (`HEATER_CTL`) | Q803 | реле |
| Зуммер | AUX8 (`BUZZER_CTL`) | Q804 | реле |
| Триггер камеры | AUX (`CAM_TRIG`) | J806 | `TRIG_*` |
| Запрос выключения ИИ | MAIN8 (`AI_SHDN_REQ`) | J601 конт. 8 | реле; ИИ по фронту корректно завершает работу |

Диагностика ключей: ток нагрузки = U(AINx) / R_IS × kILIS (R_IS = 470 Ом, kILIS — по datasheet BTS5030-1EJA,
CHECK_DATASHEET), `DEN` = 1 включает диагностику. Обрыв — ток ≈ 0 при включённом ключе, КЗ — насыщение IS.

## 4. ИИ-компьютер Firefly ROC-RK3588S-PC

Проверено по device tree ядра Linux (`arch/arm64/boot/dts/rockchip/rk3588s-roc-pc.dts`, модель «Firefly Station M3»):

- включены **UART2** (консоль отладки) и **UART7** (`uart7m2`) — UART7 использовать для MAVLink к TELEM2 Pixhawk
  через J601 (конт. 2, 3); уровень выводов — 3.3 V или 1.8 V по домену питания банка GPIO — **проверить**;
  при 1.8 V — преобразователь уровня в кабеле;
- вентилятор: `pwm-fan` на **PWM11**, питание от входа 12 V (`vcc12v_dcin`) — вентилятор радиатора 12 V
  подключается к разъёму вентилятора Firefly, обороты регулирует Linux по температуре SoC;
- сторожевой таймер платы: ИИ даёт импульсы на `AI_WDI` (J601 конт. 6) в окне TPS3430 (заводские тайминги,
  окно выбирается перемычками JP701/JP702) и взводит его через `AI_WD_ARM` (конт. 7) после загрузки;
- сигнал `AI_SHDN_REQ` (конт. 8): при получении — `systemctl poweroff`, затем Pixhawk снимает питание.

## 5. Что сделать в программе (следующий этап)

1. Драйверы PX4: TMP117 (0x48) и SHT4x (0x44) -> публикация в uORB (`sensor_temp`/`sensor_hygrometer`) и в лог.
2. Модуль PX4 «avionics_board»: логика вентилятора/нагревателя по TMP117/SHT4x, контроль токов ключей по ADS1115,
   напряжение шины Б, отказы -> сообщения в QGC.
3. Сервис на ИИ: MAVLink (UART7) к Pixhawk, пульс сторожевого таймера (GPIO), обработка `AI_SHDN_REQ`.
4. Параметры: `ADC_ADS1115_EN = 0`, строки запуска из п. 2, функции выходов AUX из п. 3.
